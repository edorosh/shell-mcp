# shell-mcp v2.1 macOS spike results

Date: 2026-10-26 · Host: Mac mini, Apple Silicon (`uname -m` arm64), macOS 26.6.2,
Node v25.9.0 (`process.arch` arm64), npm 11.12.1, no `~/.microsandbox` home.
· Package: published `@edorosh/shell-mcp@1.0.2`, SDK `microsandbox` 0.7.11.
Retires the risks in the [v2.1 macOS design §3](2026-10-26-shell-mcp-v2.1-macos-design.md#3-stage-a-spike-on-a-real-mac).

**Decision:** 1.0.2 works unchanged on an Apple Silicon Mac. Every check passed,
including the 12 acceptance criteria, Claude Code and Copilot with the
`deny-shell.sh` hook. v2.1 needs no fix to the server's behavior; it adds CI,
an Intel/Rosetta message, docs and a release.

## Setup findings

1. **No separate `msb` install is needed.** The SDK's macOS package
   `@superradcompany/microsandbox-darwin-arm64@0.7.11` holds `bin/msb` (40 MB),
   `lib/libkrunfw.5.dylib` (25 MB) and the `.node` addon (31 MB). `--check`
   reported `runtime: msb 0.7.11 from sdk_package (~/.npm/_npx/…/microsandbox-darwin-arm64/bin/msb)`.
   `npx -y -p microsandbox@0.7.11 msb create ubuntu:24.04 …` created and started
   a sandbox with no hypervisor, entitlement or code-signing prompt.
2. **The bundled `msb` is not on `PATH`.** `spike/stop-check.mjs` and integration
   criterion 10 call a plain `msb`; they ran after
   `export PATH="<clone>/spike/node_modules/@superradcompany/microsandbox-darwin-arm64/bin:$PATH"`.
3. **`msb` refuses a bind mount through a symlink.** With `~/dev` a symlink to a
   folder on another volume, `msb create … --mount-dir "$HOME/dev/tmp-proj:/workspace"` failed:
   `error: invalid config: bind mount host path /Users/<you>/dev/tmp-proj goes through symlink /Users/<you>/dev; use the resolved path /Volumes/<disk>/dev/tmp-proj or add follow-root-symlinks`.
   Creating it with the resolved path (`pwd -P`) worked.
4. **zsh without `interactivecomments`** passes `# comment` text to commands, so
   copy-paste blocks in macOS docs must not contain inline comments.
5. **The guest is aarch64** (`Linux macspike 6.12.113 … aarch64 GNU/Linux`), so
   images need an arm64 variant. `ubuntu:24.04` has one.

## `--check` (Step 2, 3c)

All six lines `ok` (config, native module, runtime, sandbox, shell, mount) with
`--host-root` set to the resolved `/Volumes/<disk>/dev/tmp-proj`, and again with
the symlinked `/Users/<you>/dev/tmp-proj`: `readdir` follows the symlink, so the
mount check matched (10 entries) both ways.

## Mount edge cases (Step 3)

- **Unicode:** a name with é decomposed (`e` + U+0301, bytes `65 cc 81`) and one
  with é precomposed (U+00E9, bytes `c3 a9`) both appear in the guest byte for
  byte. Both files exist side by side on the host.
- **Case:** the guest wrote `echo x > /workspace/mixedcase.txt` while
  `MixedCase.txt` existed. No `mixedcase.txt` appeared on either side, so the
  write went to `MixedCase.txt`: the guest sees the host's case-insensitive
  file system. Docs note: a git repo with paths that differ only in case
  behaves as it does on the Mac, not as on Linux.

## SDK probe (Step 4, `spike/sdk-check.mjs`)

Identical to the Windows results in [spike-results.md](spike-results.md),
findings 1 to 12: stream events, deadline kill (partial output kept, guest
`pgrep` rc=1), `exit 3`, spawn failure as one `undefined` event, job logs and
exclusive cursors, `invalid_cursor`, kill then `job_not_running`, `exec_failed`,
`sandboxNotFound`. `import("microsandbox")` loaded with 136 exports.

Stopped sandbox: `Sandbox.get` gives `status: "stopped"`; `connectWithTimeout`
throws `SandboxNotRunningError` / `sandboxNotRunning`.

## Held connection across `msb stop` (`spike/stop-check.mjs`)

| Step | Result on macOS |
|---|---|
| Shell on a fresh connection, sandbox running | ok |
| `Sandbox.get` after stop | `SandboxNotRunningError`, `sandboxNotRunning` |
| `shell` on the old connection | `SandboxNotRunningError`, `sandboxNotRunning`, "sandbox "macspike" has no agent endpoint (is it running?)" |
| `execStream` on the old connection | same as above |

On Windows the old connection failed with `GenericFailure` and a
`\\.\pipe\msb-agent-…` message, which the backend treats as a lost connection
and re-checks. On macOS the SDK reports `sandboxNotRunning` directly, which the
backend already maps to `not_running`.

## Integration run (Step 5)

`SHELL_MCP_IT_ALLOW_STOP=1 npx vitest run test/integration.test.ts`:
**12 of 12 passed** in 11.5 s. Criterion 12 took 5.3 s, the same ~5 s mount
lag for host-side deletes as on Windows. `npm ci` warned `EBADENGINE` for
`vitest@5.0.5` on Node 25 (vitest wants 22, 24 or ≥26); development only.

## Clients (Steps 6, 7)

- **Claude Code**, `.mcp.json` with `npx -y @edorosh/shell-mcp@1.0.2` and the
  resolved host root: connected; `uname -a` reported Linux aarch64; `pwd`
  reported the host path; a background `sleep 5 && echo done` polled as running
  twice, then `exited (exit code 0)` with `done`.
- **GitHub Copilot in VS Code**, Copilot harness, with
  `examples/copilot/.github/hooks/` copied in: the built-in terminal `uname -a`
  was refused ("Denied by preToolUse hook: hook exited with code 2"), and
  `sandbox-shell` returned Linux. **`deny-shell.sh` is verified on macOS.**

## Not exercised

- Intel Macs and x64 Node under Rosetta (no `darwin-x64` SDK package exists).
- A separate home install of `msb` on macOS (`origin: home`).
- Global install (`npm i -g`) on macOS.
- `output_gap`, `launch_unconfirmed`, `sandboxReplaced` (same as Windows).
