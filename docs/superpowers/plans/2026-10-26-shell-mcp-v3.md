# shell-mcp v3 Sandbox from Config Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a create mode: with `--image` and `--mount`, shell-mcp creates, reuses or starts its microsandbox sandbox itself, while today's attach mode keeps working unchanged.

**Architecture:** `src/config.ts` turns flags into a `mounts` list (both modes) and an optional `MachineSpec` (create mode). `src/paths.ts` maps over several mounts. A new `src/backend/provision.ts` owns everything SDK-specific about creating, comparing, starting and recreating; `MicrosandboxBackend` gets its connection from it in create mode instead of `Sandbox.get()`. `src/index.ts` warms the provisioner after the MCP handshake, and a new `src/prepare.ts` runs it in the foreground for `--prepare`.

**Tech Stack:** TypeScript 7, Node 22+, vitest 5, `microsandbox` SDK 0.7.11 (pinned), `@modelcontextprotocol/sdk`.

**Spec:** [docs/superpowers/specs/2026-10-26-shell-mcp-v3-create-sandbox-design.md](../specs/2026-10-26-shell-mcp-v3-create-sandbox-design.md)

## Global Constraints

- `microsandbox` stays pinned at exactly `0.7.11`; supported `msb` is 0.7.11.
- No code path runs agent commands on the host, and `src/` never mentions `child_process` (X1, X2; `test/no-host-exec.test.ts`). Provisioning goes through the SDK only.
- stdout carries only MCP while serving; diagnostics and provisioning stages go to stderr (C9). `--check` and `--prepare` print to stdout and never serve.
- Attach mode (no `--image`) behaves exactly as 1.1.0: same flags, messages, `Sandbox.get()` per connection.
- Create mode never stops or removes a sandbox on exit, and never recreates without `--recreate`.
- `--recreate` and `--prepare` are flags only, with no env var.
- Network in create mode: egress and ingress denied by default; DNS allowed only when a domain rule exists; private, LAN, loopback, link-local, metadata and host groups never allowed.
- Flags change in three places: `src/config.ts`, `src/usage.ts`, the table in `docs/configuration.md`.
- Docs: placeholders `C:\Users\<you>\...` and `/Users/<you>/...`; pin `@edorosh/shell-mcp@1.2.0`; never `npx shell-mcp`; zsh blocks without inline `#` comments.
- Commit prefixes: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
- Release version `1.2.0`.

## Review Focus

1. A Windows `--mount` whose host part has a drive letter and whose guest part has a colon-free path (`C:\Users\<you>\dev\my proj:/workspace:ro`), including spaces. Must parse to host `C:\Users\<you>\dev\my proj`, guest `/workspace`, read-only. Test in Task 3.
2. A sandbox stopped by the user while the server runs, in create mode: the next tool call must start it again (not report `not_running` forever). Test in Task 5.
3. Host-path comparison on Windows must ignore drive-letter and path case (`c:\users\...` vs `C:\Users\...`), or every restart reports a false mismatch. Test in Task 4.
4. Two tool calls arriving while provisioning runs must share one attempt (one `create`, not two). Test in Task 4.
5. `SHELL_MCP_MOUNT` with a trailing `;` or empty entries must not produce an empty mount. Test in Task 3.

```ts
export interface OwnedConfig {
  image: string;
  mounts: { guest: string; host: string; readonly: boolean }[]; // sorted by guest
  network: string;   // canonical JSON of the policy
  cpus?: number; memoryMib?: number;
}
export function networkPolicy(spec: MachineSpec): object;          // plain policy data, spec §3
export function wantedOwned(spec: MachineSpec, mounts: Mount[]): OwnedConfig; // uses hostResolved
export function ownedFromSdkConfig(cfg: unknown): OwnedConfig;     // field paths from the spike
export function compareOwned(have: OwnedConfig, want: OwnedConfig, platform: NodeJS.Platform): string[];
export type Inspect = { state: "absent" } | { state: "mismatch"; diffs: string[] } | { state: "ok"; status: string };
export interface ProvisionDeps { loadSdk(): Promise<ProvisionSdk>; platform: NodeJS.Platform }
export class Provisioner {
  constructor(name: string, spec: MachineSpec, mounts: Mount[], opts: { recreate: boolean }, deps: ProvisionDeps);
  /** Create, start or reuse; one attempt at a time, shared by concurrent callers. */
  ensure(onStage?: (line: string) => void): Promise<SdkSandbox>;
  /** Last stage line, e.g. "pulling ubuntu:24.04, 60%"; "" before the first attempt. */
  progress(): string;
  inspect(): Promise<Inspect>; // read-only, for --check
}
```

`ProvisionSdk` is the structural slice of the SDK used here (`Sandbox.builder`, `Sandbox.get`, `Sandbox.startDetached`, `Sandbox.remove`, handle `status`/`config()`/`stop()`/`connectWithTimeout`), declared in this file like `SdkModule` in `microsandbox.ts`.
