# shell-mcp v2.1 macOS Hosts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Apple Silicon macOS a supported host: macOS CI, a targeted message for Intel Macs and Rosetta, macOS docs, and release 1.1.0.

**Architecture:** Server behavior is unchanged (the spike showed 1.0.2 works on macOS). One pure helper, `nativeHint`, in `src/runtime.ts` picks the hint shown when the native module or runtime cannot load; `src/check.ts` and `checkRuntime` both use it. Everything else is CI config and docs.

**Tech Stack:** TypeScript 7, Node 22+, vitest 5, GitHub Actions.

**Spec:** [docs/superpowers/specs/2026-10-26-shell-mcp-v2.1-macos-design.md](../specs/2026-10-26-shell-mcp-v2.1-macos-design.md) · Spike: [v2.1-macos-spike-results.md](../specs/v2.1-macos-spike-results.md)

## Global Constraints

- `microsandbox` stays pinned at exactly `0.7.11`; supported `msb` is 0.7.11.
- Supported Macs: Apple Silicon with an arm64 Node. No `os`/`cpu` fields in package.json.
- Mac message, verbatim after the SDK error: `macOS needs Apple Silicon and an arm64 Node (this Node is x64: an Intel Mac, or Node running under Rosetta)`.
- Every other platform keeps the hint `reinstall shell-mcp without --omit=optional on this OS and CPU`.
- No code path runs agent commands on the host (X1; `test/no-host-exec.test.ts`). Diagnostics go to stderr while serving (C9).
- Docs: README stays minimal, detail in `docs/`. Placeholders `C:\Users\<you>\...` and `/Users/<you>/...`; never a real user, machine or volume name. Pin `@edorosh/shell-mcp@x.y.z`; never `npx shell-mcp`.
- zsh/sh code blocks in docs contain no inline `#` comments.
- Release version `1.1.0`.

## Review Focus

1. darwin/arm64 with a missing native package (e.g. `--omit=optional`) must keep the generic reinstall hint, not the Apple Silicon one. Test in Task 1.
2. linux/x64 and win32/x64 failures keep the generic hint. Test in Task 1.
3. While serving, a darwin/x64 runtime failure reaches the stderr log line with the Mac message (via `runtimeLogLine`). Test in Task 1.
4. `scripts/check-pack.mjs` must pass on macOS (non-Windows spawn path, `/tmp` under `/private`). Covered by the CI job in Task 2.
5. After the version bump, no `@edorosh/shell-mcp@1.0.2` pin is left in README, `docs/` or `examples/`. Grep check in Task 4.

### Task 1: `nativeHint` for unsupported Macs

**Files:**
- Modify: `src/runtime.ts` (replace the `hint` const; extend `checkRuntime`)
- Modify: `src/check.ts:45-52` (native step) and `CheckDeps`
- Modify: `src/index.ts` only if a call site needs the new optional args (it should not)
- Test: `test/runtime.test.ts`, `test/check.test.ts`

**Interfaces:**
- Produces: `export function nativeHint(platform?: NodeJS.Platform, arch?: NodeJS.Architecture): string` in `src/runtime.ts`, defaults `process.platform` / `process.arch`.
  Returns the Mac message when `platform === "darwin" && arch === "x64"`, else the generic hint (both from Global Constraints).
- Produces: `checkRuntime(sdkVersion: string, deps?: RuntimeDeps, host?: { platform: NodeJS.Platform; arch: NodeJS.Architecture }): Promise<RuntimeCheck>`; failure messages become `` `${text(e)}; ${nativeHint(host.platform, host.arch)}` ``.
- Produces: `CheckDeps.arch?: NodeJS.Architecture` (tests only, like `timeoutMs`). The native step's message becomes `` `${msg(e)}; ${nativeHint(config.platform, deps.arch ?? process.arch)}` ``.

- [ ] **Step 1: Write the failing tests**

In `test/runtime.test.ts`:

```ts
describe("nativeHint", () => {
  it("names Apple Silicon on darwin/x64", () => {
    expect(nativeHint("darwin", "x64")).toBe(
      "macOS needs Apple Silicon and an arm64 Node (this Node is x64: an Intel Mac, or Node running under Rosetta)");
  });
  it.each([["darwin", "arm64"], ["linux", "x64"], ["win32", "x64"], ["win32", "arm64"]] as const)(
    "keeps the reinstall hint on %s/%s", (p, a) => {
      expect(nativeHint(p, a)).toBe("reinstall shell-mcp without --omit=optional on this OS and CPU");
    });
});

it("uses the Apple Silicon hint when no runtime resolves on darwin/x64", async () => {
  const r = await checkRuntime("0.7.11", depsThatThrow("no msb"), { platform: "darwin", arch: "x64" });
  expect(r).toEqual({ ok: false, message: "no msb; macOS needs Apple Silicon and an arm64 Node (this Node is x64: an Intel Mac, or Node running under Rosetta)" });
  expect(runtimeLogLine(r)).toContain("macOS needs Apple Silicon");
});
```

(`depsThatThrow` stands for however the existing "fails with a reinstall hint when no runtime resolves" test builds its deps; reuse that.) Existing tests at lines 47-64 must keep passing: give them `{ platform: "linux", arch: "x64" }` so they don't depend on the CI host.

In `test/check.test.ts`, extend `setup` with an optional `arch` passed into `deps.arch`, then:

```ts
it("fails the native step with the Apple Silicon hint on darwin/x64", async () => {
  const { run } = setup({ sdk: async () => { throw new Error("cannot find module"); }, config: cfg({ platform: "darwin" }), arch: "x64" });
  const { code, lines } = await run();
  expect(code).toBe(1);
  expect(line(lines, "native module")).toBe("FAIL    native module: cannot find module; macOS needs Apple Silicon and an arm64 Node (this Node is x64: an Intel Mac, or Node running under Rosetta)");
});
it("keeps the reinstall hint on darwin/arm64", async () => {
  const { run } = setup({ sdk: async () => { throw new Error("x"); }, config: cfg({ platform: "darwin" }), arch: "arm64" });
  const { lines } = await run();
  expect(line(lines, "native module")).toContain("--omit=optional");
});
```

Pin `arch: "x64"` in the existing "fails the native step with the hint" test.
