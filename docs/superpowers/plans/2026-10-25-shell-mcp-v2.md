# shell-mcp v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish shell-mcp to npm as `@edorosh/shell-mcp` so that a Windows user installs and configures it from a client config line (`npx -y @edorosh/shell-mcp@<version> ...`) without cloning or building the repo.

**Architecture:** No change to the MCP server. New: package metadata for publishing, three CLI modes (`--version`, `--help`, `--check`), a runtime check built on the SDK's `resolveRuntime()`/`resolveRuntimeVersion()`, a pack check that runs the installed bin on Windows CI, and a tag-triggered release workflow using npm trusted publishing.

**Tech Stack:** As v1 (TypeScript ESM, Node ≥ 22, `@modelcontextprotocol/sdk`, `zod`, `microsandbox` exact pin, `vitest`), plus GitHub Actions on `windows-latest` and npm ≥ 11.5.1 for trusted publishing.

**Spec:** [v2 design](../specs/2026-10-25-shell-mcp-v2-npm-design.md) (decisions, findings, CLI and release design). The [product spec](../../product-spec.md) and [v1 design](../specs/2026-10-25-shell-mcp-design.md) still govern server behavior. Read the v2 design before starting.

## Global Constraints

- Package name exactly `@edorosh/shell-mcp`; bin name `shell-mcp`. **Never write `npx shell-mcp`** (the unscoped name is an unrelated package; running it would execute a stranger's code on the host, A1). Every npx example carries the scope and an exact version.
- No change to tool names, parameters, flags, defaults or result text from v1.
- `src/` still MUST NOT import `child_process` (X1, X2; enforced by `test/no-host-exec.test.ts`). The runtime check uses the SDK's `resolveRuntime()` and `resolveRuntimeVersion()`, which spawn nothing.
- In MCP mode stdout carries only MCP messages (C9). `--version`, `--help` and `--check` write to stdout because they never start MCP.
- `microsandbox` stays an exact pin. A runtime mismatch is a warning in MCP mode and never stops the server (C7).
- Anything that needs the native module or a sandbox is injected, so unit tests run on Linux CI without `msb`.
- Host: Windows only (N6). Do not add an `os` field to `package.json`.
- Every commit message ends with the session's `Co-Authored-By` trailer.

**Environment note:** The development sandbox has Node but no `msb` and no KVM. Task 2 and Task 10 run on the user's Windows host. Everything else runs anywhere; CI covers Windows for the pack check.

## Review Focus

1. **The published tarball is exactly what we think.** File list, shebang, no `private`, exact `microsandbox` pin, `repository.url` equal to the GitHub repo (provenance fails otherwise). Pinned in Task 7.
2. **The installed bin starts through npm's Windows shim** (`shell-mcp.cmd`) from `npx --no-install` and `cmd /c`, and the no-flag run prints the config error on stderr with nothing on stdout. Pinned in Task 7.
3. **`--version`/`--help` win over config errors**, and `--check` never writes to the sandbox or the host. Pinned in Tasks 3 and 5.
4. **A home-installed `msb` of a different version** is reported by `--check` as `FAIL` and by MCP mode as a warning, without stopping the server. Pinned in Task 4.
5. **Releases cannot publish a version that does not match the tag or lacks a changelog entry.** Pinned in Task 8.
